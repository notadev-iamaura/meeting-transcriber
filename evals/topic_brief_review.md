# 주제 검색 검수

전체 회의에서 주제만 입력한 첫 답변을 평가한다. 수정 전후 비교용 질문과, 최종 설치본에만 처음 물어볼 질문을 미리 나눈다. 기존에 평가했던 질문과 회의는 별도로 기록한다.

1. 원문을 읽고 질문마다 정답 회의, 관련 안건의 발언 구간, 결정·후속 작업·일정의 기대 내용을 적는다. 담당자, 조건, 제안과 확정의 차이, 뒤에서 정정한 내용도 포함한다. 원문에 없는 항목은 ‘미정’ 또는 ‘언급 없음’으로 표시한다. 질문과 정답 파일의 지문을 수정 전에 보관한다.
2. 같은 회의 자료로 설치본의 **전체 회의** 채팅에 질문마다 새 대화를 만들어 한 번씩 요청한다. 회의·날짜 필터는 비워 두고 원래 질문, API 응답, 응답 시간, 실행 버전, 원문 지문과 모델 호출 여부를 보존한다. 재시도 결과는 별도로 적는다.
3. 정답 회의가 답변에 나왔는지와 무관한 회의가 추가됐는지를 따로 센다. 각 결정·후속 작업·일정은 해당 회의의 **해당 표시란**과 그 안에서 연결한 근거만 보고 채점한다. 다른 표시란이나 출처 미리보기에만 나온 내용은 점수에서 제외한다.
4. 표시란마다 ‘충족·부분·누락 또는 오류’를 기록한다. 같은 안건의 핵심 사실과 조건이 정확하면 충족, 일부가 빠지면 부분이다. 제안한 날짜를 확정 기한으로 바꾸거나 다른 안건의 작업을 넣은 경우는 오류다. 미정인 항목을 정확히 미정으로 표시하면 충족이다. 원문에 근거가 있는 항목을 미정으로 표시하면 누락이다. 세 표시란이 모두 충족되고 무관한 회의를 추가하지 않은 질문만 전체 충족으로 센다.
5. 인용마다 원문·화자·시각 또는 회의록 발췌·문서 지문을 확인한다. 별도로 인용된 근거가 **그 표시란의 주장**을 뒷받침하는지 읽는다. 회의에 없는 주제도 한 번 묻고, 검색을 완료한 경우와 메모리 부족 등으로 중단한 경우를 구분한다.

실제 사내 회의의 질문과 응답은 로컬의 비공개 검수 경로에 둔다. 공개 회귀 테스트는 합성 전사와 실제 로컬 검색 경로를 사용한다.

```sh
.venv/bin/python -m pytest tests/test_topic_slot_quality.py -q
```
