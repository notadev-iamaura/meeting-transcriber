# Recap 2026.11.27 Zoom 녹음 안정성

2026년 11월 27일 `main` 소스 배포 기록입니다. 기준 커밋은 `c2a8de7`입니다.

## 변경 내용

- Swift 캡처 헬퍼는 입력 형식, 변환, 쓰기 대기열, WAV 쓰기 등에서 처음 확인한 실패를 기록합니다. 장치 정지와 파일 마감에 들어가기 전에 이미 확인된 오류를 전달합니다.
- Python 녹음기는 입력 프레임 단절이나 비정상 종료를 감지하면 오류를 알립니다. 종료 중 뒤늦게 받은 진단도 프로세스 종료 코드와 함께 로컬 로그에 남깁니다. 허용된 진단 필드만 기록합니다.
- 이미 종료됐거나 입력 파이프가 닫힌 프로세스의 `q` 전송을 건너뜁니다. 전송 도중 파이프가 닫히는 경우도 정리하고 부분 WAV를 보존합니다.

## 다음 중단에서 확인할 로그

로컬 로그에서 `CoreAudio 녹음 실패 진단`을 검색합니다. 같은 PID의 녹음 시작 로그와 대조할 수 있습니다.

| 필드 | 의미 |
| --- | --- |
| `stage` | 최초로 확인한 실패 단계. 예를 들어 `input_layout`은 입력 형식, `audio_convert`는 변환, `writer_queue`는 쓰기 대기열, `wav_write`는 WAV 쓰기입니다. |
| `error_domain`, `error_code` | 오류 계열과 해당 계열의 코드 |
| `exit_code` | Python이 확인한 헬퍼의 종료 코드 |
| `last_input_frame_at`, `frame_time_source` | UTC 기준 입력 시각과 출처. `helper`는 헬퍼에서 받은 입력 시각, `meter_received`는 앱이 마지막 음량을 받은 시각, `unknown`은 시각을 확인할 수 없는 경우입니다. |

## 검증

- Swift에서 WAV 쓰기 실패를 주입해 마감 전에 최초 진단을 한 번 받고, 마감 후 WAV에 저장된 PCM을 읽을 수 있음을 확인했습니다.
- 실제 uvloop에서 종료 코드 `2`를 주입했습니다. 감시기, 최대 시간 자동 정지, 늦게 도착한 진단 각 조건에서 미처리 예외 0건, 오류 알림 1회, 유휴 복귀, 부분 WAV 보존을 확인했습니다.
- 30분 이상 실제 Zoom 통화에서 스피커·이어폰 전환과 마이크 음소거·해제는 별도 검증이 필요합니다. 이전 중단의 최초 원인 확인에는 실제 통화에서 수집한 진단이 필요합니다.
