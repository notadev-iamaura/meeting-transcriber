# 분리 녹음 검증 기록 — 2026-11-17

## 수정 후 판정: 로컬 앱 반영 완료

아래에서 재현한 세 결함을 수정했다. 실제 설치 후보의 Whisper Large-v3 Turbo와
Senko로 최종 6조건을 검사해 본인 발화 **17/17**, 엄격 겹말 **11/11**, 전체 핵심어
**57/57**을 보존했다. 잘못 추가된 본인 발화는 0개였고 원본 WAV 해시는 6/6 유지됐다.
같은 합성 발화를 조건별로 반복한 결과이며, 독립된 17명의 화자를 검사한 수치는 아니다.

| 최종 후보 조건 | 본인 발화 보존 | 0.35초 초과 겹말 보존 | 추가 본인 발화 |
|---|---:|---:|---:|
| 작은 음성 + 피크 0.99인 단일 클릭 | 4/4 | 3/3 | 0 |
| 말소리 없는 선풍기형 잡음 −50dBFS | 0/0 | 0/0 | 0 |
| 작은 음성 + 겹말 중 4ms 큰 잡음 | 4/4 | 3/3 | 0 |
| 작은 음성 + 120ms 큰 충격음 | 4/4 | 3/3 | 0 |
| 상대 무음 + 최대 100ms RMS −60dBFS 본인 음성 | 1/1 | 0/0 | 0 |
| 짧은 응답 네 개 | 4/4 | 2/2 | 0 |

0.223초짜리 `네.`도 상대 음성과 완전히 겹쳤지만 `나`로 정확하게 전사됐다. 이 응답은
0.35초 초과인 엄격 겹말 분모에는 들어가지 않는다. 작은 음성은 원래 진폭의 0.022배다.
120ms 충격음은 최대 100ms RMS −8.54dBFS이며 입력에서 46샘플이 실제 PCM 포화된
조건이다. `두 장` → `2장`처럼 표기 차이가 있었으며 이를 발화 누락으로 세지 않았다.

수정 내용:

- 순간 최대 피크 대신 활성 프레임의 중앙 음량으로 전사용 사본을 보정한다. 포화
  제한은 해당 샘플에만 적용하며 큰 잡음 하나 때문에 마이크 트랙 전체를 제외하지 않는다.
- 보정된 사본을 기존 의존성 Silero의 패키지 내 CPU 모델로 검사한다. 발화가 없는
  잡음은 Whisper에 보내지 않는다. 짧은 발화를 보존하는 낮은 문턱과 앞뒤 여유를 쓰고,
  긴 파일은 중첩 블록으로 읽은 뒤 절대 시간 구간을 정렬·합친다. 원본은 변경하지 않는다.
- 확인된 분리 녹음은 유효 샘플이 있으면 작은 평균 음량만으로 녹음 종료 단계에서
  삭제하거나 전처리 전에 격리하지 않는다. 발화 확인을 통과한 사본도 다시 음량으로
  거절하지 않는다. 일반 오디오의 음량, 최소 길이, 전체 디코딩, 파일 정체성 검사는 유지한다.
- native/FFmpeg 오류 코드 또는 강제 종료는 실패로 처리한다. 짧은 부분 파일도 보존하고
  성공 콜백·전사 큐 게시를 차단하며 기존 오류 이벤트로 화면에 알린다.

실제 subprocess 오류 코드 1/2 × 짧은/긴 파일, SIGTERM 뒤 코드 0, 멀티트랙 한쪽
실패 순서를 포함한 종료 회귀 검사가 통과했다. 블록 경계, 극소 음성의 사전 허용,
증폭을 끈 전사 연결, 80ms 음성의 녹음 종료·원본 보존도 추가했다.

초기 수정 코드의 탐색 11조건에서는 본인 26/26, 겹말 18/18, 추가 본인 0을 확인했다.
큰 백색잡음·충격음만 있는 마이크, 작은 음성+에코, 92초까지 무음인 입력과 블록 경계가
포함된다. 탐색 도중 후속 코드 수정이 있어 이 수치는 최종 후보 결과와 분리한다.

최종 후보의 코드·설정 해시, 입력 조건, JSON 결과와 로그는 로컬의
`benchmark_runs/20261117_split_recording_fixed/candidate-final/` 및 같은 폴더의
`README.md`, `candidate-final.log`에 있다. 모든 실제 모델 호출은 오프라인이며
실사용 데이터와 분리했다. 처리시간 변동이 커 이번 결과로 속도 개선을 주장하지 않는다.
모든 사람·장치·현실 소음, 실제 Zoom 통화, 말소리가 완전히 가려진 경우까지 완벽함을
증명한 결과는 아니다. 사용자가 요청한 로컬 검증 범위에서 위 재현 결함의 해소를 확인했다.

실제 앱은 유휴 상태에서 백업 후 교체하고 재실행했다. HTTP health, startup readiness,
녹음 idle, 네이티브 창의 회의 18개·대기 0개를 확인했다. 핵심 소스 12개의 해시가
검증본과 같고 기존 입력 파일 19개·원시 전사 18개·설정이 그대로다. 모델 시험 뒤
추가한 변경은 앱 health 반환값의 bool 타입 명시뿐이며 해당 단위 검사 8개가 통과했다.
로컬 번들 검사와 Swift helper 컴파일도 통과했다. 서명·공증 배포는 별도 범위다.

게시할 변경만 추출한 독립 스냅샷에서 기본 전체 테스트를 실행했다. **4,189 passed,
2 failed, 1 skipped, 268 deselected**였고, 두 실패는 실제 시스템 Python/사용자 HF
캐시가 개입하는 기존 테스트였다. 테스트 환경을 격리한 뒤 관련 다섯 모듈 전체를
새 스냅샷에서 재검사해 **176 passed**를 확인했다. 앞서 발견한 두 HF offline
fixture도 같은 방식으로 격리했다. 제품의 인증·모델 다운로드 정책은 바꾸지 않았다.
이 수정 뒤 전체 suite를 다시 실행한 결과라고 표현하지 않는다.

입력 음량·화자 표시 브라우저 검사 **5 passed**, 설치한 번들의 코드를 직접 import한
녹음·분리 트랙 회귀 검사 **109 passed**도 확인했다. 전체·후속 검사 로그와 선별

## 증거와 범위

로컬 재현 스크립트·합성 입력·결과 JSON·로그는 git에서 제외된
`benchmark_runs/20261117_split_recording_audit/`에 보존한다. `reproduce.py`는
전처리와 오류 종료를, `verify_models.py`는 설치 앱의 실제 모델을 검사한다.
두 스크립트는 사용자 회의와 분리된 임시 데이터 경로를 쓰며 후자는 오프라인
환경변수 `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1`로 실행한다.

이전 실기기 시험의 겹말 3/3 보존과 미지정 구간의 추가 문장 11개는 당시 결과
기록을 재확인했다. 그 시험의 원음은 보관되지 않아 11개의 원인을 이번에 다시
판정하지 않았다. 대신 발화가 없는 것이 확실한 생성 잡음에서 환각을 새로 재현했다.
이번에는 실제 마이크를 녹음하거나 Zoom 통화를 하지 않았다.

작업 폴더에는 다른 기능의 미커밋 변경도 다수 있다. 이 검증에서 제품 코드는
수정하지 않았으며, 다음 게시 전에는 분리 녹음 변경과 필요한 의존 변경만
선별해 검토해야 한다.
